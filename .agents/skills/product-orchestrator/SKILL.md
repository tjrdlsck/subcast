# Product Orchestrator

## 시작 규칙

1. `AGENTS.md`를 읽는다.
2. `docs/project-state.md`의 현재 변경 단위, 단계, Allowed Scope, Protected Scope를 확인한다.
3. `docs/current/system-overview.md`, `module-map.md`, `test-baseline.md`를 기준선으로 확인한다.
4. 현재 단계 문서와 이미 승인된 이전 문서만 필요한 범위로 읽는다.
5. 사용자의 최신 요청이 기존 변경 단위의 피드백인지 새 변경인지 판단한다.

`docs/project-state.md`가 다른 작업 흐름을 가리키거나 현재 작업 폴더에 미커밋 변경이 있으면 덮어쓰지 말고 충돌을 보고한다.

## 단계 순서

1. Discovery
2. Product
3. Requirements
4. Design
5. Tasks
6. Testing
7. Implementation Ready
8. Implementation

Legacy 애플리케이션의 기능 변경은 저장소가 정한 `docs/current/` 기준선과 `docs/changes/current/` 형식을 우선한다. 각 응답에서 현재 단계의 문서 하나만 작성하거나 수정한다.

`archive/`는 기본 컨텍스트와 코드 탐색에서 제외하며, 사용자가 특정 파일의 검토 또는 복원을 요청한 경우에만 읽는다.

커밋을 수행할 때는 한글 메시지를 기본으로 사용한다. 제목에는 변경 목적을 쓰고, 본문에는 변경 내용·주요 파일·검증 결과·미해결 사항 또는 위험을 기록한다.

## 승인 규칙

- `승인`, `좋아`, `확정`, `이대로 진행`, `다음 단계로`, `문제없어`, `해당 문서 승인`처럼 의미가 명확한 표현만 해당 문서 전체 승인으로 처리한다.
- 질문, 부분적 긍정, 일부 항목에 대한 동의는 승인으로 처리하지 않는다.
- 승인되면 현재 문서의 상태와 승인일을 기록하고 다음 단계 문서로 이동한다.
- `impact-analysis.md`, `design.md`, `tasks.md`, `testing.md`가 모두 승인되기 전에는 구현하지 않는다.
- 구현 시작 승인을 별도로 확인한 뒤 태스크를 하나씩 처리한다.

## 요구사항 처리

정보가 부족할 때만 최대 3개의 핵심 질문을 한다. 답이 없어도 안전한 기본값을 사용할 수 있으면 가정으로 표시한다.

피드백은 추가·수정·삭제·질문·승인·이전 결정 변경으로 분류한다. 이전 승인 문서에 영향을 주면 영향받는 문서, 무효화될 결정, 되돌아갈 단계를 먼저 보고하고 자동 수정하지 않는다.

## 토큰 효율 및 코드 탐색

- 먼저 `rg`로 함수·클래스·라우트·셀렉터·에러 위치를 찾는다.
- 300줄 초과 파일은 전체를 출력하지 않고 대상 주변의 제한된 범위만 읽는다.
- 승인된 이전 문서 전체를 응답에 재출력하지 않고 결정과 변경 요약만 제공한다.
- API 계약, 데이터 스키마, 라이브러리 타입과 함수 시그니처를 추측하지 않는다.
- 대규모 추출·분리는 가능한 경우 저장소의 기존 스크립트를 재사용한다.

## 구현 및 검증

- Allowed Scope 밖 파일과 Protected Scope 파일은 수정하지 않는다.
- 한 번에 하나의 작은 태스크만 구현한다.
- 수정 직후 관련 단위·통합·정적 검증을 실행한다.
- 디버깅은 전체 traceback과 로그를 먼저 읽고 원인을 좁힌 뒤 최소 수정한다.
- Codex 세션에서는 Codex CLI를 다시 호출하거나 자기 자신에게 교차 검증을 요청하지 않는다. 외부 Codex 호출 절차는 Antigravity 전용이다.
- 검증 로그가 없거나 실패하면 완료로 선언하지 않는다.
- `.antigravity/rules.md`와 `.agent/agents/product-orchestrator/agent.md`는 항상 보존한다.

## 응답 형식

문서 작성·수정 후 다음만 요약한다.

- 현재 단계
- 작성 또는 수정한 문서
- 핵심 결정
- 가정과 미결정 사항
- 이전 문서와의 일관성
- 검토가 필요한 부분
- 다음 선택: `승인` / `수정: ...` / `질문: ...` / `되돌리기: 단계명`

구현 완료 보고에는 변경 파일, 실행한 검증 명령, 결과, 남은 위험을 포함한다.
